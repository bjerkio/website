This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```sh
pnpm dev        # dev server
pnpm build      # static build to dist/
pnpm preview    # serve dist/
pnpm lint       # biome lint --apply (writes fixes)
pnpm format     # prettier --write . (also rewraps Markdown prose, proseWrap: always)
pnpm exec vitest run                                 # tests (no `test` script exists)
pnpm exec vitest run src/__tests__/utils.test.ts -t "should format date"
```

CI runs `pnpm lint` + `pnpm build` on push to `main`, and `pnpm format` + `pnpm build` on PRs.

## Deployment

Firebase Hosting, project `bjerk-io`. PRs get a 30-day preview channel on the `dev` target; `main` deploys live to the `prod` target; pushing `next` or `next-*` deploys to next.bjerk.io.

`firebase.json` holds the prod-only redirects, CSP and cache headers. The site was previously English-routed, so every Norwegian route has a legacy redirect there — **renaming or adding a route means updating those redirects**, and adding any external script requires extending `script-src` in the CSP.

## Architecture

Astro 4 static site, Norwegian (`lang="nb"`), no UI framework. Alpine.js handles the little interactivity there is (color scheme on `<html>`, mobile nav).

**Content collections** (`src/content/config.ts`) are the data model — `project`, `post`, `event`, `partner` (Markdown) and `people` (JSON, `type: "data"`). All zod-validated at build time, so a bad frontmatter field fails `pnpm build`. Content collections share a `defaultFields` helper (title/description/social-media overrides/image with a min-width refinement). `post.author` uses `reference("people")`, resolved in pages with `getEntries`.

**Layouts** form a chain:

- `src/layouts/default.astro` — the shell every page passes through. Owns all `<head>` SEO (title/description/OG/Twitter), JSON-LD injection via `schema` prop, GoatCounter analytics, and the global CSS custom properties (`--color-*`, `--container-width`) in its `<style is:global>` block. Its `Props` type is the documented SEO contract; page frontmatter is spread straight into it.
- `page.astro` / `service-page.astro` — Markdown wrappers, selected per file with `layout: "@layouts/page.astro"` in frontmatter. `service-page.astro` additionally builds a BreadcrumbList schema and merges any `schema` from frontmatter.

**Routing**: `src/pages/*/index.md` for static Norwegian pages, `[...slug].astro` + `getStaticPaths()` over a collection for `artikler` (posts), `arbeid` (projects), `arrangementer` (events).

**Styling** is hand-written CSS scoped to each `.astro` component, using the custom properties from `default.astro`. No Tailwind or CSS framework.

**Icons** come from `unplugin-icons`: `import X from "~icons/ph/github-logo"` (`@iconify-json/ph` and `@iconify-json/tabler` are installed; add a set as a devDependency before importing from it).

**Path aliases**: `@components/*`, `@layouts/*`, `@assets/*`.

Dates are formatted for Norwegian (`nb` locale, `Europe/Oslo`) in `src/utils.ts` — the only unit-tested code.
